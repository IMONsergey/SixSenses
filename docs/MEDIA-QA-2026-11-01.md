## Additional manual acceptance scenarios

The following are manual instructions. No execution result is recorded here for the complete checklist, including delayed-image races, gesture cancellation and physical multi-touch behavior.

### Gallery

- With normal motion, use Next and Previous. The requested image must decode before a 450 ms opacity crossfade over the opaque previous photograph. No empty background should be exposed; the original image crop and preview composition remain intact.
- Delay the next image request, press Next several times, then Previous. Only the latest request may become active. The counter, preview and enlarged photograph must correspond to the displayed selection. A failed request preserves the visible image; retry may load it again.
- Swipe horizontally and confirm exactly one move with no unintended zoom dialog. Swipe vertically to scroll the document, then horizontally again. Cancelled capture must not retain an old gesture; an intentional subsequent tap or keyboard activation must still open the viewer.
- Change reduced motion during a transition. The decoded target should settle immediately and later navigation should not animate.

### Residence rail

- At 390 px and 600 px widths, Next/Previous and native touch scrolling must align the source cards inside the actual rail viewport. The count must agree after scroll settles. Previous is disabled at the beginning and Next at the end.
- Resize to desktop, where both cards fit. Both controls are disabled and the rail is removed from the keyboard tab order; internal residence buttons remain available. Resize back and confirm alignment/count.

### Zoom viewer

- Open a plan and a landscape photograph before cache warmup. Loading must not display the previous asset. The viewer shows a loading status, then the actual source image; failed loading gives a retry-by-reopen instruction.
- Zoom with buttons, wheel, keyboard and pinch. Pan boundaries follow the contained image dimensions, preventing panning into empty letterbox space. Fit returns to the centered image, and boundary zoom buttons disable.
- Pinch with two pointers, lift one and continue dragging with the remaining pointer. Position must continue without a jump. Repeat with pointer cancellation, lost capture, resize and close/reopen. Resize keeps the current scale while reclamping the image and resetting active gesture baselines.
- Check Chromium and WebKit with reduced motion on/off. No motion module API posts are made by these scenarios.

## Regression harness correction

The zoom test measures the visible contained image rectangle, checks that ArrowRight reveals content toward the right, verifies no empty space can be exposed by panning, and reaches the actual image edge before resetting. The earlier assertion incorrectly expected a positive translation; the image moves left when the viewport explores content toward the right. Gallery assertions wait for decoded selection, and viewer assertions wait for visible image readiness. The corrected common browser suite passed in job `20261101T124919-e3044c77a5`.

The enhanced motion harness also waits for the complete application state after native dialog closing: the expected set of open dialogs, both document lock classes, menu expansion state and released vertical overflow. Native `open=false` and restored focus alone can precede the queued `close` handler. The corrected harness passed in job `20261101T130704-34b4912f4d`.
